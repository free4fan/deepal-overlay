# DESIGN — позиционирование оверлеев (id-first)

Статус: **инфраструктура + аудит** (бриф `prompt.md`, шаги 1–2).
Поведение приложения этим коммитом **не изменено**.

## Сетka безопасности (с v2.10.44 и далее)

- **Синтетический self-test** (`python3 tools/test_diff_golden.py`, телефон
  не нужен): 4 сценария, которые обязаны держатьсь на каждом релизе —
  идентичный прогон = clean (0 hard); node+pill сдвинулись вместе = только
  NODE-CHG; node стоит, пилюля сойдёт = PILL-CHG; пилюля расширилась на
  месте = PILL-CHG. Запускать ДО правки (засвидетельствовать, что харнес
  жив) и после (что diff по-прежнему ловит мутации).
- **Golden**: `tools/capture_golden.sh` снимает `tools/golden/<run>/<screen>/`
  (a11y.xml + overlays.txt + **pills.json** + screenshot.png + manifest.txt);
  список экранов — `tools/screens.json`. Скрипт сам запускает Deepal (только
  через `.SplashActivity`), включает сессию золотых дампов (flag) и снимает
  её по выходу (`trap disarm EXIT`). Перед правкой: снять baseline; после:
  `python3 tools/diff_golden.py <baseline> <new> --json report.json`.
- **Источник rects пилюль = приложение** (`pills.json`). Overlay-окна
  (а11y-сервис) **невидимы** и `uiautomator dump` (0 узлов), и `dumpsys window`
  (окна без package/title) — проверено live на устройстве. Пока существует
  флаг `files/golden_capture` (создаётся и удаляется скриптом `run-as`, то
  есть только на DEBUG-установке; на релизе `run-as` заблокирован → механизм
  автоматически инертен, 0 затрат на прод-пути) app сам пишет в
  `files/pills.json` точную геометрию активных пилюль: `key, id, text,
  node[x0,y0,x1,y1], pill[x,y,w,h], est, sp, fsPx` (троттлинг 700 мс).
- **HARD-сигналы = дельта baseline→new** (правила 3/5 брифа: «было/стало»,
  любой ненулевой сдвиг не по цели = регрессия, подлежащая обоснованию):
  `NODE-CHG` — а11y-узел сдвинулся/поменял размер на >±2px;
  `PILL-CHG` — пилюля сдвинулась **относительно своего узла** на >±2px,
  появилась или исчезла. «Относительно узла» — скролл приложения двигает
  узел и пилюлю вместе → это не дефект (проверено синтетическим тестом).
  Отношение считается по 4 сторонам L,T,R,B; R/B — от правой/нижней кромки
  узла до края пилюли (абсолютные углы): сдвиг позиции относительно узла на
  любой стороне = CHG, а чистое расширение ширины label-пилюли (растёт R)
  тоже = CHG — честное «изменились размер/покрытие», не артефакт формата
  (app-дамп хранит пилюлю [x,y,w,h], узел [x0,y0,x1,y1]; diff переводит в
  абсолютные углы до расчёта). view_profiles в HARD-пути **не участвует** →
  baseline чистой сборки всегда зелёный.
- **Источник узлов для NODE-CHG (закреплено 10-18)**: узлы сводятся по
  `(id,text)`, при том a11y.xml несёт **CJK-оригинал** (`锁`), а pills.json
  — **перевод RU** (`Замок`) → микс a11y↔pills структурно ложный. На
  экране выбирается **единый текстовый домен для обеих сторон**: оба
  a11y-dump свежи (суперпокрывают ids своих пилюль **по множеству
  resource-id**, coverage ≥ 0.6 — по тексту проверять нельзя!) →
  NODE-CHG по полным CJK-деревьям; иначе (a11y отсутствует/устарел —
  живой 3D/карты-экран часто не входит в a11y-idle: `uiautomator dump`
  пишет `could not get idle state` и **не переписывает** файл) → обе
  стороны из node-rect'ов `pills.json` (RU). Capture дополняет: удаляет
  `/sdcard/_g.xml` **до** каждого dump (leftover-дерево иначе молча
  уезжает в прогон — поймано 10-18: ~20 снимков возвращали 47-узловое
  shop-дерево прошлой сессии), success = строка `UI hierchary dumped`,
  валидация id-set, ретрай ×8; при неудаче a11y.xml отсутствует — diff
  сам встаёт на pills-фолбэк. Инварианты: self-diff по a11y = clean
  (0 hard); self-diff по pills (base vs base без a11y) = clean.
- **ADVISORY (информационно, не гейт)** — абсолютная id-first модель
  покрытия: позиция CJK-бега из профиля (`g=center` → центр узла,
  `p=padStart` → контент-край, иначе — оба кандидата), label/block,
  overhang ≤2px за рамку узла. Это **вход для шага 3** (пометка mixed
  gravity), а не истина: пока профиль неполный, advisory печатает
  противоречия профиль↔код как находки аудита, а не как фейлы. Обнаружено:
  `tvTopTitle` (профиль `g=center, p=20dp`; код ставит CJK на контент-край
  ~56px) → mixed-кейс для шага 3.
- **moratorium** (жесткий, до отмены):
  1. новых геометрических гейтов `if (h>X && y<Y && w>est·k)` — НЕ ДОБАВЛЯТЬ;
     сначала доказать невозможность через id-профиль;
  2. один PR = одна причина (≥2 гейтов — разбить);
  3. правка только с golden-diff: baseline до, diff после, в отчёте — список
     изменённых узлов и причина каждого;
  4. регрессия (нецелевой сдвиг) — либо баг, либо «осознанно расширено» в
     CHANGELOG;
  5. словарь (dict) и геометрия — в разных релизах.
- **Мораторий ретроспективен (закреплено 10-19)**: касается и legacy-кода.
  Текущий набор гейтов (A)–(F) + shape-классов — **замёрзший список**: не
  растёт, сокращается только через id-профиль (шаг 4). Исторические fix-
  правки, расширения (E) v2.10.40 и (F) v2.10.42–43, внесённые до правил,
  закреплены как frozen legacy (см. TASKS «Рабочие правила»). Корректность
  условия замороженного гейта (багфикс, без нового поведения) — отдельно,
  допустима, но каждый сдвиг — по golden-diff с объяснением.

### Шаг 3 — ИТОГ (расширение профиля по baseline v2.10.43)

`view_profiles.json`: **7265 → 7282 id** (добавлены 17 id из baseline;
все прежние записи побайтово неизменены, словарь/профиль = отдельный
релиз, геометрия приложения **не трогается** — рантайм читает из профиля
только `sp`+`sl`, а у 17 новых их нет). Факты взяты из
`tools/decompile_ids.py` (raw per-layout gravity) на APK v1.10.2 и cross-
сверены с observed pill↔node в baseline.

- **`g=center` (безусловно, all-center gravity — ни один layout не
  заявляет non-center горизонт)**: `tv1`, `tvAirTile`, `tv_main_car_update`,
  `tab_text`, `tv_text`, `titleTv`, `txt_title`, `item_help_center_tv`,
  `tvNegative`, `tvPositive` (двое + **`btn:1`** = hug-stadium dialog-кнопка,
  гейт (F)). Это закрывает id-профилем гейт (F): пара диалога теперь
  описана профилем, а не только px-гейтом.
- **`mx:1` (mixed gravity — оставить геометрический fallback; `g` НЕ
  заявляем)**: `tv_title`, `tv_content`, `tv_name`, `tv_num`, `title`,
  `content`, `tv_car_owner`. По правилу шага 3 mixed не маркировать как
  center — позиция остаётся «покрыть оба кандидата» до явного вердикта.
- **`tvTopTitle`** (уже был в профиле как `g=center, p=20dp`): raw gravity =
  `center:2, vert-only:12` → по decompile-критерию это **all-center** (нет ни
  одного non-center), но observed в baseline: код ставит CJK на контент-край
  ~56px, а `p=20dp`→45px. Остаётся в «Известное расхождение» — НЕ
  переключать без dedicated release с diff'ом.
- **Не добавлено `sp`** ни для кого из 17: декомпиляция не дала однозначного
  размера (у этих id размер задаётся кодом/адаптером) — по правилу «профиль
  только подтверждённые факты» лучше `sp=null`, чем догадка.

`diff_golden.py` (step-3): advisory-модель теперь понимает `mx` (mixed →
both-candidates, как сегодня) и `btn` (hug-кнопка → пилюля обязана совпасть
с узлом, `ddx=ddy=0`, stadium). `g=center`/`btn`-id проходят «clean» на
baseline.

Потом — шаг 4: `layoutFromProfile`, удаление (A)/(B)/(D) по одному релизу.
